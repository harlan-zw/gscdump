# Choose how gscdump connects to Google and Bing

Choose one mode for the current CLI profile. It applies to both Google and Bing commands.
Local Google access has two login paths. Choose who handles OAuth before you log in.

## Choose cloud or local

| Path | Sign in with | Google data requests | First command |
| --- | --- | --- | --- |
| Cloud | Your gscdump.com account | gscdump.com calls Google | `gscdump auth login --mode cloud` |
| Local, gscdump.com OAuth | Your Google account through gscdump.com | The CLI calls Google directly | `gscdump auth login --mode local` |
| Local, your Google credentials | Your Google Cloud OAuth client or service account | The CLI calls Google directly | Set credentials, then run `gscdump auth login --mode local` |

`auth login --mode cloud` or `auth login --mode local` saves the mode for later commands.
`--mode cloud` or `--mode local` overrides it for one command. `GSCDUMP_AUTH_MODE` also overrides the saved mode.
Run `gscdump auth status --json` to see the active mode. The [commands reference](/gscdump-cli/api/commands) lists profile options.

### Cloud access

Cloud login opens gscdump.com. Sign in, authorize the CLI, then [connect a Site](https://gscdump.com/app/sites/add). The CLI saves a session. You do not need to copy an API key. Hosted access follows the Site and plan. SDK integrations can use a user API key from [Agent setup](https://gscdump.com/app/developers#api-keys).

```bash
gscdump auth login --mode cloud
gscdump auth status --json
gscdump sites --json
```

The saved mode applies to later commands. For Bing, connect the Site in gscdump.com, then run `gscdump bing sites --json` and `gscdump bing status --site s_SITE_ID --json`. Use the hosted Site ID printed by `bing sites` for Bing commands.

### Local access

Both local paths send Search data calls to Google directly. Choose who handles OAuth before you log in. Google write APIs need their own scopes and eligibility.

#### Use gscdump.com for OAuth

The default login opens gscdump.com for authorization. You do not need your own Google Cloud project for this read-only path.

```bash
gscdump auth login --mode local
gscdump auth status --json
gscdump sites --json
```

#### Use your own Google credentials

For a fully local connection, create a Desktop OAuth client in Google Cloud and enable the Search Console API. Set its credentials before login. This path opens Google directly and does not use gscdump.com for OAuth.

```bash
export GSC_CLIENT_ID=your-client-id
export GSC_CLIENT_SECRET=your-client-secret
gscdump auth login --mode local
gscdump auth status --json
```

For an existing access token, set `GSC_ACCESS_TOKEN`. For renewable credentials, set `GSC_CLIENT_ID`, `GSC_CLIENT_SECRET`, and `GSC_REFRESH_TOKEN` together. `gscdump auth status --json` identifies the active source.

A service account needs Search Console Site access. Set `GOOGLE_APPLICATION_CREDENTIALS` to its JSON key path for scheduled reads. Run `gscdump auth login --mode local --service-account ./gsc-sa.json` to check it. For a remote terminal, `gscdump auth login --mode local --no-browser` prints an authorization URL; a custom OAuth client's loopback flow may need port forwarding.

Google login does not connect Bing. Run `gscdump bing login --mode local` and `gscdump bing sites --mode local --json` separately. Use the exact Bing Site URL printed by `bing sites` for local Bing commands. See the [Bing reference](/gscdump-cli/api/bing) for OAuth and API key options.

## Fix access errors

If `sites` is empty, check the Google identity and the Site's Users and permissions. If cloud mode rejects the session, run `gscdump auth login --mode cloud` again. If a local grant expires, run `gscdump auth login --mode local` again. `gscdump doctor` can check configuration. Do not paste credentials into an issue or agent prompt.
