# Review search traffic each week

Use a repeatable window so a new, incomplete Search Console day does not look like a drop.

## Choose two complete weeks

```bash
gscdump report movers --site example.com --period 7d --vs prev-period --explain
```

Check the dates in the plan. Stored Reports end on the newest synced day. Live Reports end three days ago in Google's Pacific reporting calendar. If the Store covers only part of either week, the CLI prints a sync command. [Build history](/gscdump-cli/guides/use-data/build-history) before comparing.

## Run the movers Report

```bash
gscdump report movers --site example.com --period 7d --vs prev-period --json
```

The result has Sections for changed queries and pages, decay, and near-ranking opportunities. Each Section has its own coverage and findings. Check `meta.degraded` and partial-data warnings before treating a missing finding as no change. The [Reports reference](/gscdump-cli/api/reports) lists all Sections and window options.

## Check the rows

Choose one changed page from the Report. Keep its Site and search type. Query that page for the same current dates, then the previous dates:

```bash
gscdump query --site example.com --type web --page /blog/post \
  --start 2026-08-15 --end 2026-08-21 --dimensions date,page --format table
```

Replace those dates with the Report window. Check clicks, impressions, and position together. A Report finding is a lead, not a cause. The [query guide](/gscdump-cli/guides/use-data/query-and-export) explains filters and source metadata.

| Brand mix changed | [Separate brand traffic](/gscdump-cli/guides/investigate-traffic/brand-traffic). |
