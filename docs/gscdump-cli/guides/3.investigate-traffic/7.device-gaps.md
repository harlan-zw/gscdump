# Compare traffic by device and search type

Hold the Site and dates steady. Keep web, image, video, and other search types separate.

## Hold the date window steady

Choose a complete 28-day window. Start with `web`. Keep the same dates in every query. The [query reference](/gscdump-cli/api/query) lists the `--type` and `--device` filters.

## Find device gaps

```bash
gscdump analyze device-gap --site example.com --period 28d --json
```

The Analyzer reads the Store's daily device totals. It needs a complete `dates` table for the window. Check coverage before interpreting a gap. See [Analyzers](/gscdump-cli/api/analyzers).

## Query each search type

```bash
gscdump query --live --site example.com --type web \
  --dimensions device,page --format table
gscdump query --live --site example.com --type image \
  --dimensions device,page --format table
```

Add identical `--start` and `--end` flags. These page and device combinations need `--live`; the Store has no page by device table. Compare devices within one search type. Do not add impressions from web and image results. The device-gap Analyzer has no `--type` flag.

## Check affected pages

Narrow the query with `--page /path` and compare clicks, impressions, CTR, and position. Check whether the gap appears across pages or only on one. For a possible title or result problem, use [Low CTR](/gscdump-cli/guides/investigate-traffic/low-ctr).

## Choose a follow-up

Record the Site, search type, window, device, and pages. Recheck a longer pattern with [Growth trends](/gscdump-cli/guides/investigate-traffic/growth-trends). Other questions: [Investigate traffic](/gscdump-cli/guides/investigate-traffic).
