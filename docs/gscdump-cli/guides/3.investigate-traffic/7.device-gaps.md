# Compare traffic by device and search type

Hold the Site and dates steady. Keep web, image, video, and other search types separate.

## Hold the date window steady

Choose a complete 28-day window. Start with `web`. Keep the same dates in every query. The [query reference](/gscdump-cli/api/query) lists the `--type` and `--device` filters.

## Find device gaps

```bash
gscdump analyze device-gap --site example.com --period 28d --json
```

The Analyzer compares desktop and mobile performance in its supported data. Read the window and coverage before treating a gap as real. Check the [Analyzer reference](/gscdump-cli/api/analyzers) for source support; this Analyzer may require stored data.

## Query each search type

```bash
gscdump query --site example.com --type web \
  --dimensions device,page --format table
gscdump query --site example.com --type image \
  --dimensions device,page --format table
```

Add identical `--start` and `--end` flags to each command. Compare devices *within* one search type first. Google reports different result surfaces with different behavior, so do not add their impressions together. The device-gap Analyzer does not take a `--type` flag; use filtered `query` rows for other search types.

## Check affected pages

Narrow the query with `--page /path` and compare clicks, impressions, CTR, and position. Check whether the gap appears across pages or only on one. For a possible title or result problem, use [Low CTR](/gscdump-cli/guides/investigate-traffic/low-ctr).

## Choose a follow-up

Record the Site, search type, window, device, and pages. Recheck a longer pattern with [Growth trends](/gscdump-cli/guides/investigate-traffic/growth-trends). See all [traffic investigations](/gscdump-cli/guides/investigate-traffic).
