# Read hosted Bing data and send IndexNow updates

Use `@gscdump/sdk/v1` on your server to read hosted Bing data and manage IndexNow notifications for authorized Sites.

Hosted Bing is in private preview. Direct and Local Bing (`gscdump/bing`) and Hosted IndexNow are available now. Use [Direct Bing](/gscdump-sdk/guides/read-data/direct-bing) if you want to call Bing Webmaster directly with your own credential.

## Before you start

Complete [Hosted first result](/gscdump-sdk/guides/start/hosted-first-result) and create a server client with `createGscdumpV1Client`.

| Operations | Required scope |
| --- | --- |
| `listUserBingSites`, `listSiteBingIndexingEvidence`, `listUserIndexNowSites`, `listSiteIndexNowSubmissionReceipts` | `indexing:read` |
| `getSiteBingData`, `getSiteBingDataTotals` | `analytics:read` |
| `submitSiteBingSitemap`, `configureSiteIndexNowConnection`, `verifySiteIndexNowConnection`, `submitSiteIndexNow`, `updateSiteIndexNowAutomaticSending` | `indexing:write` |

User Fleet methods take a public `userId` (`u_...`). Site methods take a public `siteId` (`s_...`).

## Check Bing state across Sites

`listUserBingSites` returns the user's Bing grant and a tagged state for each visible Site. Render the state tag you receive instead of predicting access on the client.

```ts
const bingSites = await client.listUserBingSites({
  params: { userId },
  query: {},
})

console.log(bingSites.data.grant._tag)
for (const site of bingSites.data.sites) {
  console.log(site.siteId, site.state._tag, site.callerCanAct)
}
```

Pass `teamId` in `query` to filter to one Team. A Site's `state._tag` is one of `collecting`, `verification-required`, `linkable`, `grant-required`, `reauthorization-required`, or `unavailable`.

## Read Bing traffic, totals, and Indexing Evidence

Use `getSiteBingData` for daily series across `traffic`, `pages`, `keywords`, or `crawl` datasets. Date ranges must be ordered (`YYYY-MM-DD`) and span at most 366 days.

```ts
const traffic = await client.getSiteBingData({
  params: { siteId },
  query: {
    dataset: 'traffic',
    startDate: '2026-08-01',
    endDate: '2026-08-31',
    limit: 100,
    offset: 0,
  },
})

console.log(traffic.data.sync._tag, traffic.data.rows)
```

Use `getSiteBingDataTotals` to sum ranked `pages` or `keywords` rows across the date range:

```ts
const topQueries = await client.getSiteBingDataTotals({
  params: { siteId },
  query: {
    dataset: 'keywords',
    startDate: '2026-08-01',
    endDate: '2026-08-31',
    limit: 25,
    offset: 0,
  },
})

console.log(topQueries.data.totals, topQueries.data.rows, topQueries.data.pagination)
```

Check `data.sync._tag` (`ready`, `missing`, or `unavailable`) before treating empty rows as zero traffic. `dataset: 'traffic'` reports Site totals, while `pages` and `keywords` return ranked rows rather than complete Site totals.

Read stored Bing URL observations with `listSiteBingIndexingEvidence`:

```ts
const evidence = await client.listSiteBingIndexingEvidence({
  params: { siteId },
  query: { limit: 100, offset: 0 },
})

for (const item of evidence.data.indexingEvidence) {
  console.log(item.url, item._tag, item.observedAt)
}
```

Each observation is tagged as `observed`, `unknown`, or `unavailable`. Observed items (`_tag === 'observed'`) report dated discovery and crawl observations with `uncertaintyReason: 'indexed-verdict-unavailable'`. It does not return an indexed verdict.

## Submit a Sitemap to Bing

When a collecting Site's `state.sitemap._tag` is `missing`, submit a Sitemap with `submitSiteBingSitemap`. Omit `url` in `body` to let gscdump submit the Sitemap it discovered on the Site.

```ts
const submission = await client.submitSiteBingSitemap({
  params: { siteId },
  body: { url: 'https://example.com/sitemap.xml' },
})

if (submission.data._tag === 'submitted')
  console.log(submission.data.sitemapUrl, submission.data.sitemap._tag)
else
  console.error(submission.data.reason, submission.data.retryable)
```

Bing lags after accepting a Sitemap, so `submission.data.sitemap._tag` usually reads `awaiting-bing` for up to 72 hours. Do not resubmit while the state is `awaiting-bing`.

## Configure and verify IndexNow

Check IndexNow status across all visible Sites with `listUserIndexNowSites`:

```ts
const indexNowSites = await client.listUserIndexNowSites({
  params: { userId },
  query: {},
})

for (const site of indexNowSites.data.sites) {
  console.log(site.siteId, site.connection._tag, site.acceptedUrls30d)
}
```

Configure a key with `configureSiteIndexNowConnection`. Host the key text file at the returned `keyLocation` on the Site's exact host. Then call `verifySiteIndexNowConnection`:

```ts
const configured = await client.configureSiteIndexNowConnection({
  params: { siteId },
  body: { key: 'a1b2c3d4e5f6g7h8' },
})
if (configured.data._tag !== 'disconnected')
  console.log(configured.data._tag, configured.data.keyLocation)

// Publish the key file at keyLocation, then verify:
const verified = await client.verifySiteIndexNowConnection({
  params: { siteId },
})
console.log(verified.data._tag)
```

If you host the key file at a custom path, pass an HTTPS `keyLocation` without query parameters or fragments. Keys must be 8 to 128 ASCII letters, digits, or hyphens.

## Submit URLs and read Submission Receipts

After verification (`_tag === 'connected'`), queue URL notifications with `submitSiteIndexNow`. Supply a caller-chosen `idempotencyKey` (1 to 128 characters) and up to 1,000 URLs per request.

```ts
const submitted = await client.submitSiteIndexNow({
  params: { siteId },
  body: {
    urls: ['https://example.com/docs/new-guide'],
    idempotencyKey: 'deploy-2026-11-28-01',
  },
})

console.log(submitted.data.submissionReceipt._tag, submitted.data.submissionReceipt.id)
```

A Submission Receipt proves notification receipt only, never crawling or indexing. It records whether IndexNow queued, accepted, deferred (`pending`, HTTP `202`), rejected, retried, or failed the notification. Read Google or Bing Indexing Evidence separately to check crawl or coverage changes.

List recent receipts with `listSiteIndexNowSubmissionReceipts`:

```ts
const receipts = await client.listSiteIndexNowSubmissionReceipts({
  params: { siteId },
  query: { limit: 25, offset: 0, trigger: 'manual' },
})

console.log(receipts.data.submissionReceipts, receipts.data.pagination)
```

Filter receipts by `state`, `trigger` (`manual` or `automatic`), `since` (ISO datetime), or an exact `url`.

## Enable IndexNow Automatic sending

Turn on Automatic sending so gscdump submits new and changed sitemap URLs after each sitemap update:

```ts
const updated = await client.updateSiteIndexNowAutomaticSending({
  params: { siteId },
  body: { automaticSending: 'on' },
})

if (updated.data._tag !== 'disconnected')
  console.log(updated.data.automaticSending)
```

Automatic sending requires a configured key and sends only changes observed after the switch turns on and the key verifies. Removed URLs are never sent. Automatic Submissions use at most 500 of the Site's 1,000 daily URLs.

## Handle failures and next steps

Catch `GscdumpV1Error` and log `error.code` and `error.requestId` as shown in [Errors and retry](/gscdump-sdk/guides/operate/errors-and-retry). If a Bing Site reports `unavailable`, confirm private preview access for the Site owner or use [Direct Bing](/gscdump-sdk/guides/read-data/direct-bing). For saved Google URL observations, see [Hosted indexing](/gscdump-sdk/guides/read-data/hosted-indexing).
