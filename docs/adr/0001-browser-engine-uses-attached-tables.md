# Browser engine path uses attached parquet tables, not a canonical-schema SqlQuerySource

In the browser, DuckDB-WASM is loaded against per-partition parquet files attached as views (`createAttachedTableSource`), not a fully materialized canonical drizzle schema. The browser analysis runtime (`createBrowserAnalysisRuntime`) builds its `Source` this way and dispatches via `runAnalyzerFromSource`. We previously shipped an `engine-duckdb-wasm/createEngine` that wrapped `createSqlQuerySource + browserResolverAdapter` (the canonical-schema path) — it had zero callers across this monorepo, gscdump.com, and @gscdump/nuxt, because the canonical-schema use case doesn't exist in browsers. It was deleted in 2026-05. Don't reintroduce it: any new browser source should compose `createAttachedTableSource` over the parquet attach helpers, or extend the attached-table contract.
