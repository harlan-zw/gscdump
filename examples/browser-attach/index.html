The same analyzer SQL that ships in @gscdump/analysis — rewritten to read from the attached gsc.* tables instead of read_parquet([...]). Identical results to the server-side path.

How this works

The CLI exported the live Parquet partitions into one gscdump.duckdb file (gscdump store export --out ./gscdump.duckdb --force). This page fetches it, registers it in DuckDB-WASM's virtual FS, then runs ATTACH 'gscdump.duckdb' AS gsc (READ_ONLY). In production you'd serve the file from a CDN and use ATTACH 'https://cdn/u_<id>.duckdb' with a signed URL.
